1.
• Objectif : Trouver tous les employés qui occupent le poste de "Design Engineer" (Ingénieur concepteur).
• Tables à utiliser : HumanResources.Employee
• Indices : Utilisez une clause WHERE sur la colonne JobTitle.

SELECT BusinessEntityID, NationalIDNumber, JobTitle, Gender
FROM HumanResources.Employee
WHERE JobTitle = 'Design Engineer';


2.
• Objectif : Afficher le nom (Name) et le prix de base (ListPrice) de tous les produits dont le prix est strictement supérieur à 1 000 $.
• Tables à utiliser : Production.Product
• Indices : Filtrez à l'aide de l'opérateur > et triez le résultat par prix décroissant (ORDER BY ... DESC).

SELECT Name, ListPrice
FROM Production.Product
WHERE ListPrice > 1000
ORDER BY ListPrice DESC;


3.
• Objectif : Extraire le prénom (FirstName) et le nom de famille (LastName) de toutes les personnes dont le nom commence par la lettre "M".
• Tables à utiliser : Person.Person
• Indices : Utilisez l'opérateur LIKE avec le joker %

SELECT FirstName, LastName
FROM Person.Person
WHERE FirstName LIKE 'M%'
ORDER BY LastName, FirstName;


4.
• Objectif : Afficher le prénom, le nom de famille et l'adresse e-mail de chaque personne enregistrée.
• Tables à utiliser : Person.Person et Person.EmailAddress
• Indices : Faites une jointure interne (INNER JOIN) en utilisant la clé commune BusinessEntityID.

SELECT p.FirstName, p.LastName, e.EmailAddress
FROM Person.person AS p
INNER JOIN Person.EmailAddress AS e
	ON p.BusinessEntityID = e.BusinessEntityID;


5.
• Objectif : Connaître le montant total des ventes (SubTotal) ainsi que le nombre total de commandes pour chaque territoire de vente (TerritoryID).
• Tables à utiliser : Sales.SalesOrderHeader
• Indices : Vous aurez besoin des fonctions d'agrégation SUM() et COUNT(), regroupées par la clause GROUP BY TerritoryID.

SELECT TerritoryID, SUM(SubTotal) AS TotalVentes,
COUNT(SalesOrderID) AS NombreCommandes FROM
Sales.SalesOrderHeader GROUP BY TerritoryID;


6.
• Objectif : Identifier les clients (CustomerID) qui ont passé plus de 25 commandes au total.
• Tables à utiliser : Sales.SalesOrderHeader
• Indices : Utilisez GROUP BY CustomerID et appliquez la condition sur le nombre de commandes avec la clause HAVING (et non WHERE).

SELECT CustomerID, COUNT(SalesOrderID) AS NombreCommandes
FROM Sales.SalesOrderHeader GROUP BY CustomerID 
HAVING COUNT(SalesOrderID) > 25;


7.
• Objectif : Trouver tous les produits dont le prix de vente (ListPrice) est supérieur à la moyenne globale des prix de tous les produits.
• Tables à utiliser : Production.Product
• Indices : Créez une sous-requête dans votre clause WHERE pour calculer d'abord AVG(ListPrice).

SELECT ProductID, Name, ListPrice
FROM Production.Product
WHERE ListPrice > (SELECT AVG(ListPrice)
					FROM Production.Product);


8.
• Objectif : Classer chaque commande (SalesOrderID) d'un employé selon son montant (TotalDue), du plus grand au plus petit, pour chaque employé individuellement.
• Tables à utiliser : Sales.SalesOrderHeader
• Indices : Utilisez la fonction de fenêtrage ROW_NUMBER() ou DENSE_RANK() combinée avec OVER (PARTITION BY SalesPersonID ORDER BY TotalDue DESC).

SELECT SalesPersonID, SalesOrderID, TotalDue,
ROW_NUMBER() OVER(PARTITION BY SalesPersonID 
					ORDER BY TotalDue DESC)
AS RangeCommande 
FROM Sales.SalesOrderHeader 
WHERE SalesPersonID IS NOT NULL;



9.
• Objectif : SQL Server 2025 intègre nativement les expressions régulières 
(REGEXP_LIKE, REGEXP_REPLACE). Essayez d'extraire ou 
de filtrer les descriptions de produits de la table Production.ProductDescription qui
 contiennent des formats spécifiques 
 (comme des suites de chiffres ou des structures textuelles complexes) 
 en utilisant ces nouvelles fonctions.

ALTER DATABASE [AdventureWorks2025] SET COMPATIBILITY_LEVEL = 170; 
-- "COMPATIBILITY_LEVEL = 170" = SQL Server version 2025
GO
-- C'est un délimiteur de lot (batch). 
-- Il demande à SQL Server Management Studio (SSMS) d'exécuter 
-- la commande précédente avant de passer à la suite.


SELECT ProductDescriptionID, Description 
FROM Production.ProductDescription 
WHERE REGEXP_LIKE(Description, '\d{3,}');
/* REGEXP_LIKE, C'est une fonction de recherche. 
Elle vérifie si le texte de la colonne Description correspond 
au modèle (pattern) défini en deuxième argument. 
Comme elle renvoie un type de données booléen (TRUE ou FALSE), 
elle se place directement après le WHERE.
• \d : Représente n'importe quel chiffre de 0 à 9.
• {3,} : Signifie "au moins 3 fois, ou plus".
*/


SELECT ProductDescriptionID, Description 
FROM Production.ProductDescription 
WHERE REGEXP_LIKE(Description, '\.$');
/*
• \. : En expression régulière, le point . est un caractère spécial 
qui signifie "n'importe quel caractère". 
Pour rechercher un véritable point final, 
il faut "l'échapper" en mettant un anti-slash \ devant.
• $ : Ce symbole représente la fin de la chaîne de caractères.
*/


SELECT ProductDescriptionID, Description AS Original,
REGEXP_REPLACE(Description, '\b\d{4}\b', '****') 
AS ModifiedDescription
FROM Production.ProductDescription;
/*
• REGEXP_REPLACE(chaîne, modèle, remplacement) : 
Contrairement à REGEXP_LIKE qui filtre, cette fonction modifie le contenu.
Elle cherche le modèle et le remplace par le nouveau texte spécifié 
(ici '****'). Elle renvoie la nouvelle chaîne modifiée.
• '\b\d{4}\b' (Le modèle) :
• \b : Indique une frontière de mot (word boundary). 
Cela garantit que l'on isole un nombre autonome et 
non une partie d'un nombre plus grand 
(par exemple, cela trouvera "2025" mais ignorera le "2025" 
caché dans "120255").
• \d{4} : Recherche une suite de exactement 4 chiffres.
*/
